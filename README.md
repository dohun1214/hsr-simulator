# HSR Battle Simulator

붕괴: 스타레일 전투 시뮬레이터.

최종 목표는 현재 전투 상태에서 가능한 행동을 생성하고, 실제 게임 규칙에 따라 미래를
시뮬레이션·탐색하여 **가장 좋은 행동을 추천하는 것**이다.

현재 버전은 **V0.8 — 인성치 · 약점 격파 · 격파 효과**다.

---

## 빠른 시작

```bash
# 전투 1회 자동 진행
PYTHONPATH=src python -m hsr_sim

# 미래 상태 탐색(1수) 데모
PYTHONPATH=src python -m hsr_sim --mode search --crit never

# 테스트
python -m pytest          # pytest 가 있을 때
python run_tests.py       # 의존성 없이 (오프라인 폴백 러너)
```

Python 3.10 이상. 런타임 의존성 없음.

## 구현 범위

### V0.1 — 기본 전투 시스템

- 캐릭터/적 유닛, 진영, 슬롯
- HP / ATK / DEF / SPD / 치명타 확률 / 치명타 피해
- 스탯 수정자 (기본값 x (1 + %합) + 고정합)
- **Action Gauge 기반 행동 순서** (AV = AG / SPD, 행동 후 AG 10000 복귀)
- 사이클 (첫 사이클 150 AV, 이후 100 AV)
- 행동 앞당기기 / 늦추기 / 즉시 행동 (스케줄러 레벨)
- 턴 진행, 행동 선택, 적 AI
- **전체 데미지 공식** (Base / 치명타 / 피해 보너스 / 나약 / DEF / RES / 취약 / 피해 감소 / 격파)
- 속성 약점과 저항 (약점 0%, 기본 20%)
- HP 감소, 사망, 사망 유닛의 행동 제외
- 전투 종료 판정 (승리 / 패배 / 무승부)
- 전투 로그, 이벤트/트리거 버스
- 결정론적 난수, 상태 복제, 미래 상태 시뮬레이션 API

### V0.2 — 자원과 스킬

- **스킬 포인트** (시작 3 / 최대 5, 파티 공유, 일반 공격 +1 / 전투 스킬 -1)
- 스킬 포인트가 없으면 전투 스킬이 행동 후보에서 제외됨
- **에너지** (일반 공격 20 / 전투 스킬 30 / 필살기 5 / 처치 10 / 피격 시 획득)
- **에너지 회복 효율** — 행동 기반 획득에만 적용, 고정 회복에는 미적용
- **필살기** — 턴을 소모하지 않음, 자기 턴이 아닐 때도 발동, 연쇄 발동
- 전투 스킬 / 필살기 행동과 자원 검증
- **대상 지정 단일 / 확산(blast) / 전체(aoe)** — 확산 인접 판정은 생존 유닛 기준
- 확산 스킬의 인접 대상 배율 분리

### V0.3 — 상태 효과

- **버프 / 디버프 / 기타** 3분류와 디버프 하위 분류(행동 불능 / DoT / 감속 / 나약)
- 지속시간, 중첩 상한, 재적용 정책(갱신 / 중첩 / 둘 다 / 무시)을 **효과별 데이터**로 관리
- 지속시간 감소 시점을 효과별로 지정 (소유자 턴 종료 / 턴 시작)
- 상태 효과 → 스탯 수정자 자동 동기화
- **디버프 적용 확률** `기본 x (1 + 효과 명중) x (1 - 효과 저항) x (1 - 디버프 저항)`
- 효과별 개별 저항(`debuff_res`), 버프는 판정 없이 적용
- 해제(dispel)와 해제 불가 효과, 무한 지속 효과
- **DoT** — 대상 턴 시작 시 발동, 부여 순서대로 처리, 치명타 없음, 중첩 비례
- DoT 스냅샷 모드 / 실시간 모드 양쪽 지원
- 행동 불능(CC) 시 주 행동 차단
- 스킬이 상태 효과를 부여하는 데이터 경로 (`inflicts`, `self_effects`)
- 쓰러진 유닛의 상태 효과 소멸

### V0.4 — 어그로 (도발치)

적의 공격 대상은 **완전 무작위가 아니다.** 캐릭터의 운명의 길에 따른 어그로에 비례한다.

- 운명의 길별 기본 어그로 (보존 150 / 파멸 125 / 동조·허무·풍요·기억 100 / 수렵·지식 75)
- 대상 선택 확률 = `자신의 어그로 / 살아 있는 아군 어그로 총합`
- 어그로 수정자 `기본 x (1 + 수정자 합)` — **기존 버프/디버프 시스템으로 그대로 표현**
- 도발 / 어그로 감소 상태 효과
- 어그로를 무시하는 공격(Bounce 계열)을 위한 균등 선택, 결정론적 선택(최저 HP 등)
- 유닛 정의에서 기본 어그로 직접 지정 가능

### V0.5 — 적의 행동 패턴 (AI)

실제 게임 데이터(`Config/ConfigAI/Monster_*.json` 362개)의 구조를 그대로 모델링했다.

- **고정 스킬 순환** — 613개 몬스터 템플릿 중 158개가 쓰는 가장 흔한 형태
- **효용 기반 결정(DefaultDSE)** — 조건을 평가해 점수를 내고 최고점 결정을 실행
- 조건(Predicate) 레지스트리 — 페이즈, 내부 카운터, 상태 효과 보유, 생존 인원, HP 비율, 격파 여부, and/any
- 스킬 쿨다운 (`InitialCD` / `CD`)과 AI 내부 카운터
- 페이즈별 사용 가능 스킬 (`PhaseList`)
- **행동 게이지 배수** — 스킬별 `DelayRatio`(큰 기술일수록 다음 턴이 늦다), 유닛별 `InitialDelayRatio`
- **스킬별 피격 에너지** (`SPHitBase`) — 10 이 가장 흔하지만 5/15/20/25 도 존재
- **적의 기본 효과 저항** (`StatusResistanceBase`, 0.1~0.3) — 기존 기본값 0 을 교정
- **태그 기반 디버프 저항** (`STAT_CTRL`, `STAT_DOT_Burn` ...) — 효과 id 가 아니라 태그로 조회

### V0.8 — 인성치 · 약점 격파 · 격파 효과

- **인성치(Toughness)** — 약점 속성 공격만 인성치를 깎는다
  (게임 데이터 `StanceWeakList` / `StanceBase` / `StanceDamageType` 로 확인)
- 인성치 0 → **약점 격파**. 받는 피해 배수 0.9 → 1.0, 행동 **25%** 지연,
  속성별 디버프를 **기본 확률 150%** 로 부여
- 아케론의 행적처럼 **약점 무시** 공격을 위한 예외 경로 (`ignores_weakness`)
- 캐릭터 스킬의 인성치 감소량을 실제 데이터에서 임포트

**격파 피해**

```
기본값 = 속성 배수 x 격파 기본 피해(공격자 레벨) x 최대 인성치 배수(대상)
```

- 격파 기본 피해 표는 **게임 원본** (`ExcelOutput/AvatarBreakDamage.json`, Lv80 = 3767.5535)
- 속성 배수 물리2 / 화염2 / 얼음1 / 번개1 / 바람1.5 / 양자0.5 / 허수0.5
- 최대 인성치 배수 `0.5 + 최대 인성치 / 120`

**속성별 격파 효과** — 이름은 게임 데이터의 공식 한국어 명칭이다 (StatusID 30020020~26)

| 속성 | 효과 | 기본 피해 | 턴 | 그 밖 |
|---|---|---|---|---|
| 물리 | 열상 | 일반 16% / 정예·보스 7% 의 대상 최대 HP (상한 있음) | 2 | 지속 피해 |
| 화염 | 연소 | 1배 | 2 | 지속 피해 |
| 얼음 | 빙결 | 1배 | 1 | 행동 불가, 해제 시 다음 턴 50% 앞당김 |
| 번개 | 감전 | 2배 | 2 | 지속 피해 |
| 바람 | 풍화 | 1배 x 중첩 | 2 | 일반 1 / 정예·보스 3중첩, 최대 5 |
| 양자 | 얽힘 | 0.6배 x 중첩 x 인성치 배수 | 1 | 행동 20% 지연, 피격 시 +1중첩 |
| 허수 | 속박 | 없음 | 1 | 행동 30% 지연, 속도 -10% |

**교차검증 방법.** 수치는 커뮤니티 자료에서 가져왔지만 그대로 믿지 않고,
게임 데이터의 격파 효과 정의(`MCommon_Element_*`)와 하나씩 대조했다 —
열상의 정예 분기(`ByCompareMonsterRank > 2`)와 상한 처리, 풍화의 `MaxLayer: 5`,
빙결의 `DisableAction`, 속박의 `STAT_SpeedDown`, 격파 특효 참조(`BreakDamageAddedRatio`)가
모두 자료의 서술과 일치한다. 또 우리가 게임에서 직접 뽑은 레벨별 표가 자료의
"Level Multiplier" 와 Lv1 54 / Lv95 7494.371 까지 일치했다.
자료 두 곳의 인성치 배수 식이 달라 보이는 것(`/40` vs `/120`)은 **단위 차이**이며
같은 식임을 확인했다. 과정은 [`docs/mechanics.md`](docs/mechanics.md) 8장.

**아직 미확인**: 인성치 회복 시점, 얽힘·속박이 행동을 막는지 여부
(게임 데이터에는 `DisableAction` 플래그가 있으나 자료·게임 내 설명은 지연만 말한다.
우리는 지연만 적용했다).

## 실제 게임과의 대조

| 날짜 | 사례 | 결과 |
|---|---|---|
| 2026-08-19 | 아케론 Lv80 일반 공격 → 보안의 충견 Lv56 | **예상 395.0 / 실측 395** |

```
894.14(ATK) x 1.00(일반공격 Lv6) x 1.08(번개 +8%)
        x 0.568182(DEF) x 0.8(저항 20%) x 0.9(미격파)  =  395.0
```

이 한 사례가 데미지 공식·DEF 공식·적 기본 DEF(200+10xLv)·비약점 저항 20%·미격파 0.9·
적/캐릭터 레벨 스케일링·행적 스탯·스킬 배율 추출을 **동시에** 검증한다.
`tests/test_ingame_measurements.py` 에 회귀 테스트로 고정되어 있다.

## 검증 상태

`python -m pytest` — **238개 테스트 통과**.

주요 수치는 손계산과 대조해 고정했다. 예시 (`--crit never`):

| 상황 | 계산 | 결과 |
|---|---|---|
| ATK 1000, 배율 1.0, 적 DEF 1000(Lv80 vs Lv80), 물리 약점, 미격파 | `1000 x 0.5 x 1.0 x 0.9` | **450.0** |
| 위와 동일하나 비약점 속성 (RES 20%), 적 DEF 800 | `1000 x 5/9 x 0.8 x 0.9` | **400.0** |
| 적(ATK 700) -> 캐릭터(DEF 500), 인성치 없음 | `700 x 2/3 x 1.0 x 1.0` | **466.7** |
| 전투 스킬 배율 2.0, 적 DEF 1000, 물리 약점 | `2000 x 0.5 x 1.0 x 0.9` | **900.0** |
| 확산 스킬 주 대상 (ATK 900, 배율 1.5, DEF 800, 화염 약점) | `1350 x 5/9 x 1.0 x 0.9` | **675.0** |
| 위 확산의 인접 대상 (배율 0.75, DEF 1000, 화염 비약점) | `675 x 0.5 x 0.8 x 0.9` | **243.0** |
| 화상 1중첩 틱 (ATK 800의 50%, DEF 1000, 비약점) | `400 x 0.5 x 0.8 x 0.9` | **144.0** |
| 방어력 30% 감소 후 같은 공격 | `800 x (1 - 700/1700) x 0.8 x 0.9` | **338.8** |
| 디버프 적용 확률 (기본 80%, 효과명중 +50%, 효과저항 10%, 디버프저항 20%) | `0.8 x 1.5 x 0.9 x 0.8` | **86.4%** |
| 파멸(125) / 수렵(75) / 허무(100) 파티에서 적이 파멸을 노릴 확률 | `125 / 300` | **41.7%** |
| 수렵 캐릭터에게 도발(+500%)을 건 뒤 | `450 / 675` | **66.7%** |

행동 순서도 손계산과 일치한다.
SPD 100 / 134 / 90 / 110 인 4유닛의 첫 6턴은 `A2 -> E2 -> A1 -> E1 -> A2 -> E2`.

또한 `DEF` 배수는 KQM 의 레벨 기반 식과 Prydwen 의 DEF 기반 식이
**모든 레벨 조합에서 일치하는지**를 테스트로 검증한다.

## 설계 요약

상태 / 정의 / 동작을 분리한다.

- **상태** (`BattleState`, `Unit`) — 순수 데이터만. 함수도 클로저도 이벤트 구독도 없다.
- **정의** (`UnitDefinition`, `SkillDefinition`) — 불변 데이터. 복제하지 않고 공유한다.
- **동작** — 전부 레지스트리에 등록된 구현체. 상태를 갖지 않는다.

그래서 `state.clone()` 이 싸고, 결과가 결정론적이며, 미래 상태를 대량으로 탐색할 수 있다.

새 메커니즘 추가는 다음으로 끝난다 (엔진 코어 수정 없음).

```
새 구현 작성 -> 레지스트리 등록 -> 데이터에 id 추가 -> 테스트 추가
```

이 성질은 `tests/test_extensibility.py` 에서 실제 코드로 고정되어 있다.

## 이름 처리

캐릭터/적/스킬 이름은 `LocalizedName(ko=..., en=..., ko_verified=...)` 로 관리한다.
영어 데이터를 임의로 번역해서 저장하지 않으며, 공식 한국어 명칭을 확인한 항목만
`ko_verified=True` 로 표시한다.

현재 들어 있는 유닛은 실제 게임 캐릭터가 아니라 엔진 검증용 가상 유닛이다.
